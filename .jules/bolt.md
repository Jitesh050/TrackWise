## 2024-05-19 - [Global Disable Rules vs CI Constraints]
**Learning:** In code review, globally disabling strict ESLint rules (like `@typescript-eslint/no-explicit-any` or `no-empty`) in `eslint.config.js` to silence errors and satisfy a strict CI rule is considered highly anti-pattern and a blocking offense. It degrades code quality over time. In addition, when asked to deliver ONE specific optimization, grouping entirely unrelated refactors (like React component memoization with Vite config chunking) violates the constraint.
**Action:** When asked for ONE performance optimization, submit only ONE. If the lint step fails due to existing strict rules, do not blindly disable them globally unless specifically tasked to do so; accept the non-zero exit code if it's unrelated to the specific target of the optimization.
