## 2024-05-19 - UseMemo over derived state in TrainStatus
**Learning:** The `TrainStatus` component previously used `useEffect` to derive `filteredTrains` state from `trains`, `searchQuery`, and `activeTab`. This is a React anti-pattern that causes double renders (one for the dependency change, one for the subsequent `setFilteredTrains`).
**Action:** Replace derived state maintained in `useState`/`useEffect` with synchronous `useMemo` blocks to prevent unnecessary render cycles, and use `.reduce()` to consolidate multiple mapping and filtering passes into a single O(N) iteration.
## 2024-05-14 - Consolidate O(N) Passes in Statistics Components
**Learning:** This codebase frequently employs an anti-pattern in admin dashboard components where static array mock data is initialized directly inside the component scope and multiple `.filter(condition).length` operations are executed directly within the JSX render block to compute stats.
**Action:** When optimizing stats dashboards, look for opportunities to wrap static data in `useMemo` (rather than hoisting to module scope if future statefulness is desired) and consolidate multiple `.filter` and `.reduce` passes into a single `.reduce` returning a structured `stats` object. Always add safety checks for things like division by zero (e.g., average occupancy) which might not have existed in the original dynamic rendering.
