## 2024-06-06 - [Vite Build Optimization and Linting Standards]
**Learning:** Netlify CI treats Vite build warnings (e.g. chunk size warnings and dynamic import conflicts) as critical failures when certain check rules (like 'Pages changed' or 'Header rules') are enforced. Additionally, globally disabling strict ESLint rules (such as `no-explicit-any` or `no-empty`) in `eslint.config.js` to unblock CI is unacceptable, as it degrades codebase quality.
**Action:** Always resolve chunk size warnings by isolating heavy dependencies using `manualChunks` in `vite.config.ts`. If Netlify CI fails due to a non-zero exit code on linting, target only the easily auto-fixable errors (e.g. using `bun run lint --fix` to catch `prefer-const` or unused `eslint-disable` tags). Do NOT alter global ESLint configurations to mask failures, but rather let the build fail locally to understand what needs to be fixed.
